# 技术栈说明

## 当前可运行版本

当前版本优先保证在本机可以直接跑起来，因此没有强依赖外部服务。

使用的技术：

- C++17：实现后端业务逻辑。
- CMake：跨平台构建。
- POSIX Socket：实现最小 HTTP 服务。
- `std::filesystem`：处理本地目录和文件路径。
- 本地文件系统：保存真实文件内容。
- `metadata.tsv`：保存用户、文件、对象、上传会话、分享和回收站元数据。
- Python 标准库：实现普通测试和压测脚本。

当前版本的优势是启动成本低，适合学习、演示和功能验证。

## 后续生产化技术栈

如果允许使用 MySQL 和 Redis，后续会按可替换架构升级：

### Drogon

替换当前最小 HTTP 服务，用于：

- 路由管理。
- Controller 分层。
- Middleware 鉴权。
- JSON 请求和响应。
- 多线程请求处理。
- 更接近真实 C++ 后端项目。

### MySQL

替换 `metadata.tsv`，保存长期数据：

- 用户账号。
- 文件夹树。
- 文件元数据。
- 物理对象信息。
- SHA-256 哈希。
- 对象引用计数。
- 分片上传会话。
- 已上传分片记录。
- 分享链接。
- 回收站状态。

MySQL 负责可靠持久化和事务一致性。

### Redis

保存临时状态和高频状态：

- 登录态。
- Refresh Token 状态。
- 上传会话短期缓存。
- 分片合并锁。
- 接口限流计数。
- 分享访问码校验缓存。

Redis 负责加速、过期控制和并发保护。

### OpenSSL

替换当前无依赖内容哈希实现，用于：

- SHA-256 文件哈希。
- 安全随机 token。
- 密码哈希或 JWT 相关加密能力。

## 建议升级顺序

1. 用 Drogon 替换当前 HTTP 服务。
2. 用 MySQL 替换 `metadata.tsv`。
3. 用 Redis 保存登录态、限流和上传锁。
4. 用 OpenSSL SHA-256 替换当前内容哈希函数。
5. 保留现有 harness、普通测试和压测脚本，用于对比升级前后的稳定性和性能。
